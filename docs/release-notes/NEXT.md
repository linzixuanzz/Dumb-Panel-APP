## 更新内容

> 待发布版本草稿。后续每修复一个问题、优化一个体验或新增一个功能，都先记录到这里；最终发版时再整理为正式版本号文件，例如 `v1.3.4.md`。

本轮把 APP 仓当时全部 4 条开放 issue（#2 #4 #5 #6）一次做完。

### 新增

- **任务页支持「任务视图」，与网页端共用同一份规则**（issue #4）。
  网页上建的视图现在手机上也能选用：按 **命令 / 名称 / 定时规则 / 状态 / 标签 / 订阅** 做
  「包含 / 不包含 / 等于 / 不等于」筛选，并可指定排序。视图入口在任务页「共 N 个任务」那一行，
  与分组选择器并排，没有新增常驻的筛选行。
  operator 及以上角色还可以直接在手机上**新建 / 修改 / 删除**视图。
  筛选与排序全部由面板计算，所以两端结果必然一致；面板加了新字段或新运算符，APP 不需要跟着发版。
  面板版本太老（没有这套接口）或角色不够时，入口会整个隐藏，不会报错。
  ⚠️ 视图在面板上是**全站共享**的（表里没有用户维度），手机上改一条视图，网页端所有人都会看到。

- **日志详情页新增「编辑对应脚本」**（issue #5）。
  从一条执行日志一键跳到它实际跑的那个脚本的编辑器。
  该任务不是脚本任务（比如 `curl`、内联 shell）时会明确告诉你，不会静默失灵。

- **脚本编辑页左侧显示行号**（issue #6）。
  软换行的续行按编辑器惯例留空，只在逻辑行的第一行标号。

### 优化

- **脚本编辑页的查找从占半屏的弹层换成常驻查找条**（issue #6）。
  查找条在编辑框**外面**、编辑器上方，带 `当前/总数` 计数和 上一个 / 下一个 / 关闭 三个按钮，
  边搜边看不再被遮挡，也不会被键盘顶来顶去。关掉再打开时上次的查询词还在。

- **搜索命中现在是真高亮**（issue #6）：全部命中弱高亮 + 当前那一个强高亮，配色与网页端一致。
  以前只是把选区临时染成琥珀色 2 秒。

- **脚本编辑器的背景色设置第一次真正生效**。面板里「脚本编辑器背景颜色」以前一直被输入框的
  默认填充整块盖住，等于设了没用。顺带说明：深色模式下不设置时的默认底色是 `#1E1E1E`。

- **日志详情页的操作收进右上角溢出菜单**（issue #5）：
  「复制全部 / 下载原始日志 / 编辑对应脚本」三项归到一处，标题栏图标从 4 个降到 3 个，
  窄屏上标题不再被挤到省略号。下载进行中也不再挡着「复制全部」。

- 面板的**内置 API 文档补上了任务视图那 5 条接口**，以及任务列表接口一直没写的
  `label` / `filters` / `sort_rules` 三个查询参数（面板侧改动，v3.2.0 之后）。

### 修复

- **深色模式下日志背景是白的**（issue #2）。
  面板里「日志视图背景颜色」留空时（这就是出厂默认），APP 以前不管明暗一律给白底深字。
  现在与网页端一致，按当前主题回落：深色 `#0F172A`、浅色 `#F8FAFC`；
  你自己配了颜色的话仍然一切听你的。
  另外说明 issue 里「设成 `#000000` 也没用」那一半：1.2.6 的系统设置页里那个标着
  「日志背景色」的输入框其实绑错了键，写进的是**脚本编辑器**背景。
  1.3.0 起设置页改成由面板下发的配置表驱动，这个错绑已经不存在了。

- **脚本编辑页点「下一个」不跳转**（issue #6）。
  查找游标被「每帧重写编辑器内容」的逻辑抹掉，导致每次都从头找，永远停在第一个命中。
  只在查看模式复现，所以以前看起来时好时坏。

- **搜索定位会跳偏**（issue #6）。行高原来是写死的，长行软换行之后越往下偏得越多。
  现在按编辑器的真实排版度量计算，行号栏和跳转用的是同一份几何。

- **编辑任务会让它脱离订阅托管**（issue #4，数据丢失）。
  任务编辑页保存时会把内部的订阅标签替换成订阅的显示名，导致订阅锁失效、
  详情页的「恢复为订阅默认」入口消失、下次订阅拉取可能重建一个同名重复任务。
  这个问题只在面板 v3.x 上出现（老面板不下发显示名，反而躲过了）。

- **按分组筛选会串味**（issue #4）。筛「生产」分组时，只挂了普通标签「生产」、
  根本没分组的任务也会被捞出来，然后落进「未分组」堆里。

- **脚本加载失败时会把「加载失败」四个字当成脚本内容**。
  以前失败不设错误态，编辑器照常打开、内容是那四个字，一按保存就写进真文件。
  现在改成错误页 + 重试，并且禁用保存。这条以前踩不到（从文件树点开的路径必然存在），
  但 issue #5 新增的「从日志跳脚本」入口会经常踩到，所以一并修了。

- **打开脚本时会先闪一下红色错误页**（issue #6 修复的连带）。上一个脚本加载失败后，
  下一个脚本的第一帧会读到遗留的错误态。

## v1.3.3 遗留的已知项

v1.3.3 只做了任务页虚拟化这一件事，`v1.3.2` 那份 7 条遗留**一条都没动**（见 `v1.3.3.md` 末尾的对照表），原样顺延到下面；末尾一条是本轮改任务页时**新记下**、但不在本轮范围内的：

- **`copyWith` 的「不传即清空」语义是个反复踩的陷阱**。六个列表 State 的 `error` 都是裸赋值
  （`error: error` 而不是 `error ?? this.error`），这是有意的：`load()` 开头一句
  `copyWith(loading: true)` 就能顺手清掉上次的错误。代价是**任何**不传 `error` 的
  `copyWith` 都会把它抹掉。`v1.3.1` 已修掉两处会造成用户可见问题的
  （`DepListNotifier.loadPythonRuntimes` 与 `ScriptNotifier.setKeyword`），
  但 `ScriptNotifier` 里还有约 10 处同形状的调用（`loadContent` / `saveContent` /
  重命名与移动后的 `selectedPath` 更新等）没有显式回传 `error`。
  它们目前都发生在「树已经加载成功」之后所以看不出问题，**但这个陷阱会一直在**。
  彻底的解法是把 `copyWith` 改成哨兵语义、让 `load()` 显式写 `error: null`，
  那要同时改 6 个 State、11 个 Notifier 和 25 条测试，至今没做。

- **通知渠道页在「渠道列表失败但类型表成功」时会丢掉已取回的类型表**。
  `NotificationListNotifier.load()` 并发打两个接口，渠道列表失败时 `typesFuture`
  被直接丢弃、从不 await，catch 分支只能回落到内置快照。不会崩（`_fetchTypes`
  内部吞掉所有异常），但那份已经拿到手的数据白白浪费了。注释里写明类型表要单独降级，
  所以这可能是有意的，值得确认一次。

- **`open_api_page.dart` 的权限范围仍是硬编码**，与面板服务端的 `OpenAPIAccess`
  没有任何机制绑定。面板侧 `v3.0.2` 加了测试把服务端与面板 Web 双向锁死，
  但**管不到这个仓库** —— 面板将来加第 9 个权限范围时，APP 还是会漏。
  要根治得让面板下发 scope 字典（那是另一期的事，且第 2 期方案 §6.b 已经
  明确砍掉过 `/api/system/enums`，要重新论证）。

- **`user_list_page.dart` 的两个 `library_private_types_in_public_api`**
  仍在基线 7 个 info 里。根因是 `UserListState.items` 用了私有类型 `List<_User>`。

- **APP 全仓没有任何 CI 门禁**：`.github/workflows/` 下 grep 不到 `dart format` /
  `analyze` / `flutter test`，三项全靠本地自觉。面板那边 release 前有 checks job 挡着。

- **自动登录路径遇到两步验证账号只能退回登录页重来一次**。
  `app_boot_page.dart` 的自动登录走的是同一个登录接口，但它不带 `totpCode`、
  也不认 `two_factor_required`：v1.3.2 修完之后它不再抛异常，而是发现拿不到
  `access_token`，跳到 `/login?manual=1`。行为是正确的（总比卡在启动页强），
  账号密码也会自动回填，但用户仍然要在登录页**再点一次登录**，
  才会看到验证码输入框——等于自动登录对开了两步验证的账号事实上无效。
  彻底的做法是让启动页自己接住这个中间态、直接把 TOTP 输入框推到前面，
  至今没做。

- **`login_page.dart` 的两步验证分支不清空验证码输入框**。
  `two_factor_required` 分支的 `setState` 只写了 `_needsTotp` / `_error` / `_loading`，
  没有 `_totpController.clear()`。动态码输错之后，旧的 6 位数字会原样留在框里，
  用户得先手动全选删掉才能重输，而框上那个 `x/6` 计数器还显示着 `6/6`，
  看起来像是已经填好了。纯体验问题，不影响能否登录。

- **任务页之外的长列表还没做过同样的体检**。本轮只处理了任务页，
  但「把分组/分节包进 `Column`，再塞进一个 `ListView`」这个写法是否在
  脚本、依赖、日志、订阅等页面还有同形状的复制品，没有逐页确认过。
  任务页是最先被用户反馈卡顿的一个（issue #107），不代表它是唯一一个。
