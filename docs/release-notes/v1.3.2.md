# v1.3.2

## 版本概览

这一版只有一个修复，但它堵的是一条**从 `v1.2.3` 起就断掉、连续五次发版都没被发现**的路：**开了两步验证的账号根本登不进 APP**。

现象很有迷惑性——点「登录」之后，页面上确实红字提示「请输入两步验证码」，但**页面上根本没有能输验证码的地方**，再点一次还是这句话。看起来像是提示文案写错了，实际上这条路已经断了：除非把两步验证关掉，否则永远进不去。

同一个根因还连带害死了图形验证码——滑块验证码失效时同样卡在原地。

## 修复

- **开了两步验证的账号现在可以正常登录**：输完账号密码点登录，验证码输入框会正常出现在密码框下方，填 6 位动态码即可进入。

  > 面板用 `401` 承载两步验证挑战，它表达的是「还差一步」这个中间态，而不是失败。APP 的网络层此前把所有 4xx 一律当成异常，登录请求在读到响应内容之前就被中断了，于是那段「把验证码输入框渲染出来」的代码从来没有机会执行——它在整个仓库里是一段谁也调不到的死代码。回归点是 `v1.2.3`，与「从 1.2.3 开始登不上」的反馈完全吻合。

- **图形验证码失效时不再卡死**：滑块验证过期需要重做时，现在会正常提示并重新拉起滑块。它和上一条死于同一处，一并修好。

## 说明

- 本版与面板 `v3.0.5` 配套，但**这个修复不依赖面板升级**：面板停在 `v3.0.4` 上，装了本版 APP 的两步验证登录同样能走通。
- 面板 `v3.0.5` 在服务端做了配套的契约加固——登录失败响应新增机器可读的 `code` 字段，两步验证分支补回了验证码上下文字段（影响的是**两步验证与图形验证码同时开启**时的重试链路）。这些改动**只增不删**，原有的文案与状态码一律没变，因此对旧版 APP 也没有影响。
- 修复只放宽了登录这一个接口，其余接口的错误处理、以及登录态过期后的自动续期，行为均未改变。
- 新增 `login_two_factor_test.dart`：既覆盖两种中间态的返回值，也真的把登录页跑起来，断言验证码输入框确实出现了。
