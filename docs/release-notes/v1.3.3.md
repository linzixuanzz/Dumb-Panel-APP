# v1.3.3

## 版本概览

这一版只做一件事：**任务页不再随任务数量变卡**。

任务少的时候感觉不出来，任务一多，进任务页就要顿一下，之后滚动也跟着发涩。原因不在网络、也不在服务端，而在于这一页**从来没有做过虚拟化**——不管有多少条任务，全部都会被真正建出来。这一版把渲染方式换掉了，只有屏幕上看得见的那几张卡才会被构建。

分组、全选、拖拽排序的用法一个字都没变。

## 修复

- **任务多了以后任务页卡顿**：现在只有可见区域的任务卡会被构建，任务再多也不会拖慢进页面和滚动。

  > 改动前每个分组被包进一个 `Column`，组内任务一次性展开。`Column` 没有惰性布局，有多少条任务就建多少个 widget，而每张任务卡是几十个 widget 起步。**从没建过分组的用户更糟**：整个列表只有 1 个孩子（一个装着全部卡片的 `Column`），列表自身的惰性机制被完全旁路，滚不滚动都一样卡。
  >
  > 修法是把「分组 → 组内任务」的嵌套结构摊平成一维行列表（分组头行 + 任务行，折叠的组只出分组头、不出任务行），交给惰性列表按 index 构建。数据仍然是全量在内存里的，所以分组下拉项、全选、拖拽排序的语义完全不变。

- **滚动位置记忆不再把你丢到很靠前的位置**：切走再回到任务页，能停回原来的地方。

  > 惰性列表首帧的可滚动高度只是个估算值（真实高度要等卡片陆续建出来才知道），原先一次性跳转会被夹到这个偏小的估算值上。现在改成逐帧步进，等实际高度长出来再跟上。

- **折叠分组时列表不再自己乱跳**：只要用户已经自己滚动过，位置恢复就立刻收手，不再和用户抢滚动位置。

## 优化

- **滚动位置写盘加了防抖**：原先每收到一次滚动通知就往本地存储写一次，一次快速滑动能打出几百次写。现在合并成一次；离开页面时会把最后一次没落地的位置补写上，不会丢。

- **清掉了一个从未实现的「加载更多」空壳**。

## 说明

- 本版与面板 `v3.1.0` 配套，但**服务端零改动**：这是纯客户端的渲染改造，装在任何面板版本上都能生效，不需要升级面板。

- **没有改成增量分页**，这是刻意的。分组下拉项、全选、拖拽排序都建立在「全部任务都在内存里」这个前提上：改成分页会让分组下拉项残缺、全选退化成「只全选已加载的」，而排序保存更会把未加载任务的 `sort_order` 写坏——那已经是数据损坏，不是显示问题了。所以这一轮只改渲染，不动取数。

- 新增 `task_list_rows_test.dart`，覆盖分桶、分组排序、摊平三个纯函数，共 11 条。其中一条专门盯着一个摊平后才会出现的坑：页面上只有「未分组」一个桶、不渲染分组头时，必须**连折叠状态一起忽略**——否则没有分组头就没有任何入口能再展开，上次会话遗留的折叠态会让整页任务凭空消失。
