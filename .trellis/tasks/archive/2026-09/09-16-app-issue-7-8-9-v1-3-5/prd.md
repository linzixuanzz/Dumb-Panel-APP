## 需求

### R1 — 脚本树展开状态必须在刷新后保留（#9）

- 现状：展开状态是树节点 widget 的局部 State，任何一次 `loadTree()` 都会把整棵树折叠回顶层。
  7 处写操作（新建文件/文件夹、上传、重命名、移动、复制、删除）之后都会发生。
- 要求：展开状态按目录路径记在页面级，刷新后原样恢复；目录被删除/改名时不留脏记录。
- 附带：上传弹窗的默认目录取「用户当前正在浏览的目录」，而不是只在打开过文件时才有值的 `selectedPath`。
- 验收：展开两级目录 → 上传一个脚本 → 树仍停在原处、不折叠；连传三个文件不需要重新展开；
  新建、重命名、移动、删除后同样保留。

### R2 — 新建环境变量的失败必须可见（#8）

- 现状：变量名为空时创建按钮**静默 return**，不提示也不关弹窗；服务端拒绝时是否透出原因待确认。
- 要求：空名就地报错（提示 + 聚焦输入框）；服务端 4xx 的原因原样展示，不退化成兜底文案；
  创建成功后列表立即出现新行（现有 `await load()` 需回归确认）。
- 验收：空名点创建 → 看到明确提示；用非法变量名（如 `1abc`、含空格）→ 看到面板给的具体原因；
  正常创建 → 列表出现新行，同名多账号仍可分别新增。

### R3 — 启动流程卡住时用户要能自救（#7）

- 现状：`_runBootFlow` 全程无整体超时，开屏页 UI 只有转圈 + 一行文案、**没有任何按钮**；
  一旦某步不返回，只能杀进程或清数据。
- 要求：
  - 启动流程加整体超时（单步 + 总时长），超时或异常时进入**可操作的失败态**；
  - 失败态提供：重试、返回登录、重新配置面板、清除本地会话；并显示卡在哪一步（便于用户回报）；
  - `_jumping` 可复位，重试时能真正重跑；
  - 跳转不再被 `dashboard` 预加载阻塞。
- **非目标**：不声称修掉那个未复现的根因。目标是「再卡也能走出来，并留下可诊断信息」。
- 验收（**口径已按复查结论修正**）：
  - ⚠️ 原先写的「把面板地址改成不可达地址 → 看到失败态」是**错的**：`needsInitialization()` 与 `checkInit()`
    各吞一层异常，地址不可达时 dio 15s 抛错被吃掉，启动流程正常往下走，表现是「转十几秒 → 进登录页」，
    与 v1.3.4 一致。按这条验收会误判成「功能没做」。
  - 正确的复现手法：让某一步**永不返回**（而不是报错），例如把面板地址指向一个只建连接、不回数据的端口，
    或在调试构建里把单步时限临时调到 1~2 秒。此时才会进入失败态。
  - 要验的是：失败态显示「卡在哪一步 + 原因」，四个出口（重试 / 返回登录 / 重新配置面板 / 清除本地会话）
    都在且点下去不会被路由弹回开屏页；点「重试」能真正重跑（不是停在转圈）。
  - 正常网络下启动路径与 v1.3.4 一致（不得变慢、不得多一屏）。
